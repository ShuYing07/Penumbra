## 二、逐模块详解

### 1. 九维回测假设审计 `core/quant/assumption_audit.py`

回测从来不是"跑一遍历史"那么简单，它建立在**一堆没说出口的假设**上：能成交吗？按什么价成交？成本多少？股票池有没有幸存者偏差？任何一条与现实不符，漂亮的净值曲线就是幻觉。

九个维度：**数据可用性 / 成交假设 / 流动性 / 成本 / 滑点 / 幸存者偏差 / 时间对齐 / 市场冲击 / 分红除权**。

输出统一为 **缺陷 × 证据 × 严重度 × 影响 × 修复**，例如：

```
⛔ [FATAL] liquidity · 单笔委托规模超过日均成交额
  证据：委托 100,000,000 / 日均成交 10,000,000 = 10.0 倍
  影响：回测假设全额成交，实盘根本不可能，收益严重虚高
  修复：降低仓位或按成交量上限（如日均成交额 1%）限制委托
```

设计要点：
- **完全确定性**：只看 df / config / params 的事实，不依赖 LLM、不需要网络 → 可单测、可复现、可进 CI 门禁；
- **时间对齐维度委派**给 `core/chronoaudit.audit_bars()`，复用既有 C00–C08 时间完整性检查，不重复造轮子；
- 出现任一 FATAL → `passed=False`，报告末尾给出「该回测结论不可用于任何决策」。

### 2. PIT 时点基准 `core/quant/pit_benchmark.py`

前视偏差最隐蔽的形态不是代码写了 `shift(-1)`，而是**数据本身带未来**：回测跑到 2024-03-01，财务库里却已经躺着 2023 年报（实际 2024-04-20 才公告）。代码无罪，数据有毒——这类泄漏 AST 扫不出来，只能靠**已知真相的问答题**抓。

八大事件族 × 12 道考题：**财报公告 / 分红除权 / 送转拆并 / 指数成分调整 / 停复牌 / 限售解禁 / 评级发布 / 名称与 ST 变更**。

每道题双向验证：

- **泄漏测试**（as_of 早于信息日）：必须拿不到值 → 拿到了 = `LEAK`（致命）
- **可用测试**（as_of 晚于信息日）：必须拿得到值 → 拿不到 = `MISSING`（缺陷）

两类都跑，才能区分「数据带未来」和「数据根本没接上」。评级规则：**只要有一例泄漏即 F 级**（该数据源不可用于回测）。

把 `make_event_accessor()` 换成自己的数据访问层 `access(field, symbol, as_of)`，即可在 CI 里给任意数据源打 PIT 分。

### 3. 红队对抗合规 `security/adversarial_compliance.py`

合规规则写再多，也只是"我以为它能挡住"。真正的验证方式是**派一个 AI 去攻**。

- **红队**：20 条攻击语料覆盖十大技术族（角色扮演 / 指令覆盖 / 压制免责 / 数字诱导 / 权威冒充 / 捏造前提 / 情绪施压 / 混淆绕过 / 格式挟持 / 多轮渐进）+ `mutate()` 变体生成 + `escalate()` 多轮加压；
- **蓝队**：任意 `f(prompt) -> text`，不传则用内置 `safe_defender`（自检基准）；
- **裁判**：`ai_reviewer`（话术层）+ `nsf_verifier`（约束层）**双裁**，任一不通过即判突破。

内置自检结果：

```
合规蓝队：40 次攻击 · 突破 0 · 防守率 100.0% · 评级 A
脆弱蓝队：20 次攻击 · 突破 20 · 防守率 0.0%  · 评级 F
```

`guardrail_scorecard()` 输出十大技术族得分卡，已接入 UI 表格展示。

### 4. 评审员否定式修复 `security/ai_reviewer.py`（**真实 bug 修复**）

红队自检暴露了一个真实缺陷：AI 说「我**不提供**目标价，**不建议**买入」时，`target_price` / `stock_pick` 规则照样命中——
**越守规矩越被扣分**。

修复：命中词前 12 字内若存在否定词（不提供 / 不建议 / 无法 / 拒绝 / 并非 …），判为**拒绝性引用**，不计违规。原 7 项评审测试全部仍通过（含「必涨稳赚无风险保本内幕」硬用例）。

### 5. 结论级置信度自评 `core/agents/self_assessment.py`

大模型最爱犯的错不是算错，而是**用同样的语气说确定的事和不确定的事**。

七因子加权（权重可覆盖、归一化到 1.0）：

| 因子 | 权重 | 说明 |
|------|------|------|
| 证据充分性 | 0.30 | 条数饱和 × 来源可信度（交易所 1.0 → 社交 0.3） |
| 时效性 | 0.15 | 30 天半衰指数衰减 |
| 一致性 | 0.15 | 多空/多模型分歧度 |
| 争议收敛 | 0.10 | 辩论后未解决争议数 |
| 样本量 | 0.10 | 回测 bar 数 / 观测数 |
| 稳健性 | 0.10 | 样本外衰减 |
| 模型自评 | 0.10 | 权重最低，仅参考 |

**硬约束**：无外部证据直接判「不足」并封顶 34 分 —— 与辩论引擎「无证据不成主张」同律。
每个因子输出 `contribution`，用户能看到"为什么是这个分"；`annotate()` 在结论尾部追加置信度徽标 + 限制条件，且**只做风险揭示，绝不补荐股/目标价**。

颜色纪律：涨跌语义色 `#00C853/#FF1744` **只用于涨跌**；置信度分档用中性色（蓝 `#1976D2` / 橙 `#F9A825`、`#EF6C00` / 灰 `#9E9E9E`），单测里对此有断言。

### 6. 事件图谱因果链深化 `core/event_graph.py`

原 `query_event_chain()` 只回答"能不能到"（BFS 可达性）。新增：

- `query_causal_chains(entity, event_type, depth, as_of, half_life_days, top_k)`
  → 枚举**完整路径**，强度 = 边权连乘 × 指数时效衰减，按最强排序；
- **PIT 过滤**：`as_of` 之后才首现的事件类型不得入链（且按 entity 隔离，避免跨标的污染）；
- `graph_for_ui(entity, as_of, limit)` → 力导向图数据（节点按度数定尺寸、 links 带 rel/weight、 layers 分层），前端可直接渲染；
- `format_chains()` 人读清单。

样例输出：

```
1. 强度 0.860（原始 0.860 × 时效衰减 0天）
   600519[affected_by] → 业绩预增[raises] → 经营风险
```

### 7. 统一 SQLite 底座 `core/db_util.py` + 17 个模块接入

全项目原有 30+ 处 `sqlite3.connect(...)`，各自写各自的超时，Windows 并发写会偶发
`database is locked` / `attempt to write a readonly database`。

统一入口提供五项保证：
1. 父目录（含多级）自动创建；
2. `busy_timeout` + 指数退避重试（默认 3 次）；
3. WAL **按需**开启（`wal=True`），默认不改既有 journal_mode；
4. 目标不可写时自动退化为只读连接，让读取路径继续可用而非崩溃；
5. `diagnose()` / `ping()` 连接级诊断，UI「系统自检」可直接用。

已接入：`data/cache`、`memory/long_term`、`research_journal`、`knowledge_distiller`、
`agents/evo_memory`、`research_skills`、`quant/text_grad`、`search/stock_index`、
`drawings`、`data/industry_graph`、`etl/stream_pipeline`、`collaboration`、
`human_review`、`compliance_checker`、`audit_logger`、`eval/eval_suite`、`security/audit_ledger`。

> **踩坑（重要）**：最初把 WAL 设为默认开启，结果发现 Windows 小库在"最后一个连接关闭"时要
> checkpoint + 删除 `-wal`/`-shm`，单次开销 30~40ms —— 知识库冷检索从 **43ms 涨到 210ms**，
> 直接把 `test_knowledge_harness` 的延迟断言打挂。改为**默认不改 journal_mode、WAL 按需开启**后恢复 40ms。
> **结论：并发问题交给 busy_timeout + 重试，不要默认动 journal_mode。**

## 四、踩坑与经验（写给下一轮）

1. **中文字符串里不要写 ASCII 双引号** → SyntaxError（本项目已多次栽这上面）。一律用「」，且每次写完立即 `py_compile`。
2. **pd.Series + 指定 index 会索引对齐成 NaN**：构造 DataFrame 时 Series 与 DataFrame 索引不一致会全部变 NaN（测试里 `volume` 全变 0，误报 100% 停牌）。用 list 最安全。
3. **拒绝性引用必须豁免**：合规词表过滤要处理否定前缀，否则诚实拒答的模型反而被扣分。
4. **PIT 判定要按 entity 隔离**：跨标的共享事件类型首现日期会让测试互相污染。
5. **不要默认改 journal_mode**：见第 7 节 WAL 踩坑。
6. **红队/基准类模块的 `__main__` 自检要加 sys.path 引导**：直接 `python security/xxx.py` 时 `import security.*` 会失败。
