# 03 · 踩坑与风险台账（误判→更正 + 已知坑 + 可复用方法）

## 一、【误判→证据→更正】台账（本项目专属，持续追加）
1. 误判"DeepSeek 模型名还是 deepseek-chat / deepseek-reasoner" → 核实 DeepSeek 官方文档：两名于 **2026-07-24 23:59 弃用，现在调用直接报错、无静默跳转**；现役模型为 `deepseek-flash`（V4.1-Flash）与 `deepseek-v4-pro`（V4-Pro-0813）。**更正：代码里 model 字段写 `deepseek-flash`/`deepseek-v4-pro`；且 v4-pro 在 2026-09-14 后临时路由到 flash，flash 是默认首选。**
2. 误判"Python 3.14 太新，PyInstaller 打不了包，得降 3.12" → 核实 PyInstaller 6.15.0（2025-08）已加入 3.14 支持，现最新 6.22.x 支持 3.8~3.15；3.14.4 的 forkserver 多进程 bug 已在 6.20.0 修复。**更正：不用降 Python，打包用 PyInstaller ≥6.22 即可；但仍需在一期末做打包冒烟测试提前排雷。**
3. **东财接口在本机网络的可达范围比初判更大**：原只记录 push2his.eastmoney.com 的 HTTPS:443 在 Clash TUN 下 code=000（HTTP:80 正常，真实 IP 103.220.167.80 trafficmanager.cn）→ 编码实测确认 **F10 个股资料 `stock_individual_info_em` 同样走 push2 域、443 持续 RemoteDisconnected**。**更正/对策：A 股日线已改新浪 `stock_zh_a_daily` 优先、腾讯 `stock_zh_a_hist_tx` 次选、东财末位；F10 暂优雅降级为空 dict（基本面节点 prompt 已声明"字段缺失即数据不足"），二期补雪球/新浪基本面源；`stock_zh_a_spot_em` 也不可用，实时报价走 hq.sinajs.cn（GBK + 必须带 Referer）。**
4. **akshare 函数名随小版本变动**：1.18.94 财联社电报是 `ak.stock_info_global_cls()`（列：标题/内容/发布日期/发布时间），旧资料里的 `stock_zh_a_alerts_cls` 已被删除（AttributeError）。定位方法：`[f for f in dir(ak) if 'cls' in f]` 现场列函数名，不信旧博客。
5. **LangGraph 检查点不支持 numpy 标量（msgpack）**：MemorySaver.put 报 `TypeError: Type is not msgpack serializable: numpy.float64`。根因有二：① 外部数据（行情/指标）混入 state；② **`round(np.float64, 2)`、`pyfloat / np.float64` 的结果仍是 numpy 标量，不会自动变原生**，极易漏（本次唯一漏点 tech.atr14_pct）。对策：入图前对整个 state 递归 `_to_native`（np.generic→.item()、np.ndarray→.tolist()，dict/list 递归，见 core/agents/graph.py）；定位脚本 scripts/check_state_types.py 递归扫描并打印 numpy 类型路径，值得复用。
6. **桩数据键名与节点契约不一致会"静默出空报告"**：多空节点实际传 `debate_bull/debate_bear`，mock 只判断 `node=="debate"` → 多空论据段落为空但流程全绿。对策：mock 分支用 `startswith` 覆盖同族节点；报告生成后必须人工目检一次完整段落；后续给关键段落加非空断言测试。
7. **RSI 常量序列语义需显式定义并单测固化**：Wilder RSI 在"零涨零跌"时数学上不定义；本项目约定全涨=100、全跌=0、常量=50（中性），避免把横盘误标成超买。tests/test_indicators.py 8 个用例固化（含 KDJ 手工递推值 K=66.6667、布林轨道次序等）。
8. **PowerShell 运行 --noconsole（GUI 子系统）exe 时 `$LASTEXITCODE` 为空**：进程脱离控制台，退出码拿不到。正确姿势：`Start-Process -FilePath xxx.exe -ArgumentList '--selftest' -Wait -PassThru` 取 `.ExitCode`，并查残留进程。2026-09-10 实测：PyInstaller **6.22.2 + Python 3.14.7 + PyQt6 6.11** onedir 打包/运行成功，空窗程序目录 91.4 MB，`--selftest` 1 秒泵事件后退出码 0、无残留进程——误判 2（Python3.14 不能打包）彻底证伪。
9. **工具自伤教训**：用 Edit 替换多行 f-string 时曾拼坏一行（两个 `lines.append` 粘在一起，语法虽过但语义错）。纪律：每次非平凡 Edit 后 Read 回读改动区域，不盲信工具输出。
10. **打包后挂"采集行情"不要先怀疑网络/代理**（2026-09-11 五期实测，首轮误判方向）：冻结版 --selftest 冷库停在取行情 300s 超时，开发环境同路径 2s 正常 → 加 `--nettest` 逐源诊断后真因是 **akshare 包内数据文件 `file_fold/calendar.json` 未被 PyInstaller 收集（FileNotFoundError）**，与网络无关。对策：spec 用 `collect_all("akshare")`（datas+binaries+hiddenimports 全收）。方法论：冻结环境问题先加逐源/逐模块自检模式（exe --nettest），用证据定位，不猜。
11. **akshare 新浪源在冻结环境缺 py_mini_racer DLL**：缺 `_internal/py_mini_racer/mini_racer.dll` 时新浪日线静默失败、退化到 10s 的腾讯源。对策：spec 加 `collect_all("py_mini_racer")`，新浪恢复 1.3s。规律：凡是带原生 DLL 的小包（mini_racer/grpcio/rust 扩展）都要想到 collect_all。
12. **chromadb 1.5.x 必须整体 collect_all**：仅 collect_data_files 时报 `No module named 'chromadb.api.rust'`（新版 rust 绑定含 .pyd）；collect_all 后带入 onnxruntime（约 +66MB，337.9MB 总盘，可接受；我们用自研 HashEmbedder 不依赖 onnxruntime，后续想瘦身可在验证 import 链后 excludes）。
13. **冷库首跑的建表顺序**：run_analysis 先查 decisions 反思上下文、后由 save_decision 建表，全新库告警"no such table"（dev 库有表掩盖了此问题）。对策：run_analysis 入口先 decision_log.init()。教训：冷库（空 data 目录）冒烟必须作为打包验收项，dev 热库会掩盖初始化顺序问题。
14. **系统代理会劫持回环地址，连不到本机 Ollama**（2026-09-11 本地引擎实测）：Clash Verge 设置 HTTP(S)_PROXY=127.0.0.1:7897 后，requests/openai SDK 默认 trust_env，把对 **127.0.0.1:11434** 的请求也发给代理 → 假端点冒烟全红、真机时通时不通。对策：访问本机 Ollama 一律禁代理——`requests.Session(trust_env=False)`（core/llm_local.py）；OpenAI 客户端传 `httpx.Client(trust_env=False)`（core/llm.py）。规律：任何"访问本机回环服务"的客户端（Ollama/LM Studio/vLLM/本地向量库）都要显式绕代理。
15. **Ollama daemon 不继承后来设置的代理环境变量，pull 卡 "pulling manifest" 两万次重试**：registry.ollama.ai 根路径直连返回 404（说明网络通），但 manifest 鉴权链路在 daemon 网络环境下持续失败；真因是托盘/服务在安装时启动，没有代理环境变量。对策：杀 ollama 进程→带 `HTTPS_PROXY/HTTP_PROXY=http://127.0.0.1:7897`、`NO_PROXY=localhost,127.0.0.1` 重启 `ollama serve`→重新 pull（实测 4.7GB @3.5MB/s 约 25 分钟）。注意下载在 daemon 侧进行，给 CLI 设代理无效。持久化待办：UI 下载前可做"带代理重启 Ollama"（需用户确认，杀进程有副作用）；TUN 模式也不能保证 registry 鉴权链路通，不要假设。
16. **7B 本地模型的 schema 漂移远比云端频繁，容错必须做在契约层**：qwen2.5:7b 实测输出 `confidence:"中等"`、`stance:"看涨"`、`position_pct:"25%"`、`approved:"是"`、`entry:null`、risks 元素是 `{"reason":..,"source":..}` 对象、概率给 120。若严格 pydantic 校验，8 节点会成片降级（首轮 trader 即因 entry=None 降级）。对策：schemas.py 对所有枚举/数值/布尔/文本/列表字段加 `mode="before"` 语义归一化（中文置信度映射表、动作近义词归一化、数字正则抽取、None→空串、dict 条目抽 reason 文本、范围 clamp）；另注意中文映射要按 key 长度降序匹配（"很低"不能被"低"先抢）。此加固对云端偶发漂移同样有效。
17. **教学资源抓取反爬/失效**（2026-09-11 七期实测）：Investopedia 词条全 403（Cloudflare 反爬，改浏览器 UA 仍拒），人行投教页 404（官网结构调整）。对策：弃用，换维基百科同主题词条（CC-BY-SA、稳定、不反爬，实测 zh/en 各词条均成功取正文）。规律：教学资源源要选"不反爬+URL稳定"的（维基百科 > 商业财经站）；商业站词条反爬严，不适合批量抓取。
18. **PyQt6 枚举必须用完整命名空间**（2026-09-11 七期）：`Qt.UserRole` 在 PyQt6 报 `AttributeError: type object 'Qt' has no attribute 'UserRole'`，必须 `Qt.ItemDataRole.UserRole`（`Qt.CheckState.Checked` 已是完整形式，能用）。规律：PyQt6 严格枚举，凡 Qt.xxx 的常量都要用 `Qt.枚举类.xxx` 全名，不能像 PyQt5 直接 `Qt.UserRole`；遇 AttributeError 先查是否枚举命名空间问题。
19. **Python 3.14 与 LLaMA-Factory 不兼容，训练必须独立 venv**（2026-09-11 七期）：LLaMA-Factory 官测 3.9-3.11，主 venv 3.14 装不上；且 torch 数 GB 会破坏打包。对策：独立 venv_train（Python 3.11），spec excludes 保持 torch。规律：训练是低频离线任务，独立 GPU 环境，绝不混进分发 venv；本机若仅有 3.14 须先装 3.11（scripts/bootstrap_venv_train.ps1 已就绪）。
20. **8GB 显存 QLoRA 训 7B 须保守配置**（2026-09-11 七期设计，待实测）：7B 全量 LoRA 需 ≥12GB，8GB 只能 QLoRA 4bit。保守配置：cutoff_len=512、lora_rank=8、gradient_checkpointing=true、optim=paged_adamw_8bit、per_device_train_batch_size=1，预估 6.5-7.2GB。OOM 降级序：cutoff_len→512(已)→lora_rank 8→4→换 Qwen2.5-3B-Instruct（余量大）。训练前须 `ollama stop` 释放驻留 4.7GB 显存。规律：小显存训练先保守配置一次跑通，不反复试开关（符合用户偏好）。
21. **huggingface_hub 0.36+ 对 hf-mirror.com HEAD 元数据校验失败**（2026-09-11 七期实测）：设 `HF_ENDPOINT=https://hf-mirror.com` 后，`snapshot_download` / `hf_hub_download` 对大文件（safetensors）报 `FileMetadataError: Distant resource does not seem to be on huggingface.co`。小文件（config/tokenizer）能过，LFS 大文件不行（镜像 HEAD 响应缺 `X-Linked-Etag` 等 HF 专有头）。对策：绕过 huggingface_hub，用 `hf_transfer.download(url, dest, max_files=8, chunk_size=10MB)` 多连接直下到本地目录，YAML `model_name_or_path` 指本地路径。规律：国内镜像 + 新版 hub 库 = 元数据校验不兼容，hf_transfer 是稳定兜底。
22. **hf_transfer callback 只传一个参数（downloaded），不是两个（downloaded, total）**（2026-09-11 七期）：Progress.__call__(self, downloaded, total) → `TypeError: missing 1 required positional argument: 'total'`。对策：callback 签名改 `(self, downloaded)`，total 存为实例属性（HEAD 请求预先获取 content-length）。规律：第三方库 callback 签名不能靠猜，先 `help()` 看签名或试调再写。
23. **LLaMA-Factory 0.9.5 的 `dataset_dir` 是 YAML 字段，不能作为 CLI 参数传递**（2026-09-11 七期）：`llamafactory-cli train config.yaml --dataset_dir /path` 报 `ValueError: Some keys are not used by the HfArgumentParser: ['--dataset_dir', '/path']`。对策：在 YAML 的 dataset 区块内写 `dataset_dir: D:/path/to/export`，CLI 只传 `train config.yaml`。规律：LLaMA-Factory 的 CLI 只接受 YAML 文件路径，所有参数（含 dataset_dir/template/cutoff_len 等）都在 YAML 内。
24. **回测买入测算必须在"含滑点成交价"上算且金额+费用≤现金，否则静默 0 成交**（2026-09-11 八期实测）：buy_hold 路径先按现金做满仓预算，滑点把买入价抬高 5bp 后 amount 超现金，内联代码只判断不缩股 → 美股碎股全部买不进，结果 0 成交、收益 0，且无任何报错。对策：抽 `_size_position()` 统一测算（按市场整手/碎股规则循环缩量直到含费金额≤预算），信号成交与 buy_hold 两条买入路径共用。规律：成交价≠决策价（滑点/跳空），仓位测算一律在实际 fill price 上做；"不满足条件就跳过"必须在结果里可见（0 成交时 UI/CLI 明确提示）。
25. **argparse help 字符串里的 `%` 必须写成 `%%`**（2026-09-11 八期）：help="仓位比例%（…）" 在 Python 3.14 直接 `ValueError: badly formed help string`（argparse 用 % 格式化 help）。对策：help 文本中的百分号一律转义 `%%`；default/metavar 不受影响。
26. **PyQt6 严格枚举在 pyqtgraph 同样适用**（2026-09-11 八期，坑18 同族）：`pg.mkPen(style=2)` 报 `setStyle argument has unexpected type 'int'`，须 `Qt.PenStyle.DashLine`。规律与坑18一致：PyQt6 下凡接受 Qt 枚举的第三方调用（pyqtgraph 画笔/画刷等）都要传完整枚举。
27. **offscreen 冒烟中 QWidget.isVisible() 在窗口 show 前恒为 False**（2026-09-11 八期）：验证 setVisible 切换不能用 isVisible()（依赖顶层窗口可见状态），要用 `not widget.isHidden()`（setVisible 直接改 hidden 标志，与是否 show 无关）。

## 二、已知坑与应对（编码前就内建到设计里）
### 数据源
- **yfinance 会随 Yahoo 接口变动而 break、有限流**：① 所有调用过适配器，不裸调；② 数据落 SQLite 缓存，重复分析不重复请求；③ 失败重试+指数退避；④ 多源降级（A股 yfinance 失败→akshare；加密 yfinance 失败→CoinGecko）。**历史实证：2025-09 雅虎后端校验升级，未持久化 Cookie 的脚本全线 401（用户补充调研佐证）——本机现装 1.7.0 实测可用，但必须维持缓存+降级链不动摇。**
- **akshare 是爬虫封装，接口随东财/新浪页面变动失效**：同上，适配器隔离；单个接口挂了不影响主流程，UI 标注"该数据源暂不可用"。
- **国内网络访问 Google/Coingecko 等受限**：config 内置代理项（默认 `http://127.0.0.1:7897` Clash，可关），akshare/DeepSeek 等国内源不走代理。
- **新浪日线不支持场内 ETF（2026-09-11 实测）**：`ak.stock_zh_a_daily(symbol="sh510300")` 抛 `JSONDecodeError: No value to decode`（新浪该接口只覆盖股票）；但腾讯 `ak.stock_zh_a_hist_tx(symbol="sh510300")` 完美支持（3476 行，多 turnover 列），新浪实时 `hq.sinajs.cn/list=sh510300` 也正常。应对：service.is_cn_etf 按号段识别（沪 51x/56x/58x、深 159），fetch_daily_cn 对 ETF 跳过新浪直接腾讯优先，东财 fund_etf_hist_em 末位（443 断连环境）。
- **港股口径（十期）**：市场码独立为 HK（.HK 正则须在通用"."→GLOBAL 分支之前）；港股本地时间=北京时间（9:30-12:00/13:00-16:00）；yfinance 不出 lot size（真实每手 100/200/500 因股而异），回测/模拟盘 MVP 统一 100 近似；港股费率与 A股不同（卖出印花税 0.0013、双边徵费、无最低5元佣金），ETF 免印花税免过户费必须在 default_fee 按 ticker 区分，否则 ETF 回测成本虚高。
### LLM
- **幻觉编造数字**：价格、指标、财务数字一律程序计算后以"事实清单"喂给 LLM；交易员节点 prompt 强约束"只能使用提供的数据"（TradingAgents 的 price grounding 教训）。
- **输出不合法导致流程崩**：每个节点 pydantic schema 校验 + JSON 解析失败自动重试（≤2 次），仍失败则该节点降级为"数据不足"结论而不是中断。
- **非确定性**：结构化节点 temperature 调低（0.2~0.3）；每次分析完整落盘（输入快照+输出），便于复盘。
- **长流程中途失败成本高**：LangGraph checkpoint，每节点落 SQLite，可续跑；LLM 调用统一重试与超时。
- **成本失控**：默认 flash；缓存优先；token 用量逐节点记账写日志。
### 回测/模拟（point-in-time 纪律，TradingAgents 两次大版本才修好的坑）
- 回测某历史日期时，只能使用"该日期收盘前可得"的数据：行情用截至当日的缓存、新闻只用发布时间≤当日的、财务用当时已披露的财报（而非后来修订版）。
- 模拟盘成交按规则价（次日开盘/收盘），不许用未来价格；决策日志记录决策时刻的完整快照。
### 打包（PyInstaller）
- **chromadb 1.5.x 含 rust 扩展 + onnxruntime，体积 338MB 且必须 collect_all**：spec 已配 `collect_all('akshare'/'py_mini_racer'/'chromadb')` + collect_data_files('pyqtgraph')；akshare 还要 file_fold 数据文件、新浪源要 mini_racer.dll（均实测，见台账 10-12）。
- 用 **onedir 模式**（onefile 每次解压到临时目录、启动慢、易被杀软误报）；PyQt6/pandas/numpy 官方 hook 已支持。
- **数据目录用 exe 旁置便携式**：config 检测 `sys.frozen`，PROJECT_ROOT=exe 所在目录；windowed 下 sys.stdout 为 None，日志只落文件；入口设 socket.setdefaulttimeout(30) 防第三方库无超时挂死。
- 打包后必须在**干净目录（空 data/、无 Python 环境）**冒烟运行验证：本项目内置 `exe --selftest`（冷库 mock 全链路，退出码+selftest.log）与 `exe --nettest`（逐源网络诊断）。
- GUI 用 windowed 模式；验证退出码用 `Start-Process -Wait -PassThru` 取 `.ExitCode`（windowed 进程 $LASTEXITCODE 为空，见台账 8）。
- 涉及多进程的代码入口加 `multiprocessing.freeze_support()`。
### Windows/中文
- 所有文件读写 `encoding="utf-8"`；控制台/日志避免 GBK 崩溃（TradingAgents v0.2.4 专门修过 Windows UTF-8）。
- 路径用 pathlib，不用硬编码反斜杠。
### 合规
- 程序定位学习研究，报告页脚与启动页固定免责声明："仅供学习研究，不构成投资建议；股市有风险，决策需谨慎；历史表现不预示未来收益。"
- 不接券商实盘、不自动下单；加密货币波动极大，风险提示单独标注。
- API key 只存 `.env`（已在 .gitignore），不写进日志、不进打包产物。

### 参数寻优（十二期）
- **平原评估不能用全网格极差归一**：当最优点与邻居差距很小（如夏普 1.00/0.97/0.95）时，全网格极差也只有 0.05，极差归一后邻居必然接近 0 分，把"平原"误判为"尖峰"。根因：平原场景极差本身≈邻居差异，分母和分子同源。对策：按指标业务语义给固定容忍带（sharpe±0.1、收益±5pct、calmar±0.2），robust=邻居落入容忍带的比例，0~1 可解释。
- **平原 ≠ 跨期稳健（真实案例教训）**：SH510300 ma_cross 全样本平原 robust=1.0 的 (10,60)，walk-forward 中 IS 夏普 0.735→OOS -0.242（分位0.25 失效）。任何推荐必须同时看平原评级与 OOS 排名分位，UI/CLI 均强制双指标展示，缺一律不算通过。
- **calmar 除零**：最大回撤≈0 时年化/回撤爆炸，分母 max(|dd|,0.01) 且 dd<0.01% 时改返年化×100 的惩罚性大值。

### AI 信号回放（十一期）
- **回放信号必须与真实 decisions 物理隔离**：回放是"假装在历史做决策"，若写入 decisions 表，会被 inject_context 注入后续真实分析、被 decision_stats 计入胜率、甚至进模拟盘联动。方案：独立 ai_replay_signals 表 + run_analysis(persist=False/as_of) 双开关不写 decisions/RAG，selftest 用前后计数断言防回归。
- **时点切片要四处都切**：只截 bars 不够——quote 必须用切片末根 K 线构造（不能调实时）、新闻按 published_at<=asof 过滤（日期不可解析的保守丢弃，宁可漏不可偷看未来）、反思上下文必须置空（反思是时点之后才产生的信息）；patterns 传切片 bars 即可天然无未来。
- **选点时间基准只能来自数据**：回放点从 bars.index 实际交易日生成（warmup≥120 保证指标有效、末点距末尾≥20 保证评估有答案），不要用系统当前时间；合格点不足直接 ValueError，禁止伪造静默。
- **mock 桩与 prompt 文案耦合导致回放全观望**：LLMRunner._mock 看多条件写死匹配"低于30"字样，而技术 prompt 实际输出"超卖"，mock 批量回放几乎全中性。这是既有演示桩特性（不改，避免影响 selftest 观望断言）；验证多空评估逻辑用单测构造数据，真实信号回放用 `--engine deepseek`（充值后）。
- **UNIQUE(batch_id,ticker,asof) 与同点多样本**：同一批次同一时点只允许一条信号（INSERT OR REPLACE 幂等）；测试不要造同时点两条，会被覆盖。selftest 用固定批次名 SELFTEST 实现重复跑幂等不膨胀。

### 盯盘/自选股（九期）
- **新表需在 UI 实例化时建表**：watchlist 表若延迟到 selftest 后段才 init，WatchlistTab._load_list 先查表会崩 `OperationalError: no such table: watchlist`。教训：每个持有 SQLite 表的 Tab/模块，应在 `__init__` 里 `init()` 建表（幂等），不依赖外部先调。
- **无效标的错误隔离**：盯盘扫描对 yfinance 不识别的 ticker 会抛 `'currentTradingPeriod'` 等错；`engine.scan_all` 必须 per-item `try/except` → `status=—无数据`，绝不拖垮整轮扫描（selftest 用 TESTWATCH 验证此纪律）。
- **QSystemTrayIcon offscreen 不可用**：selftest/无桌面环境 `isSystemTrayAvailable()` 返回 False，建托盘前必须判，跳过且不影响主流程断言。
- **美股时段跨午夜**：北京 21:30(夏)/22:30(冬) 开盘到次日凌晨，凌晨段须按"前一日是否工作日"判断（周一凌晨不算上周五延伸）；夏令时用纯 date 公式不引 zoneinfo 保打包体积。
