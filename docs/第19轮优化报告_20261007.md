## 二、模块一：AI Agent 工具调用层（最高优先级，已完成）

## 三、模块二：Claim-level 结构化多空辩论（已完成）

`core/agents/debate_engine.py`

把原来"各说 3-5 条理由"的自由文本辩论，升级为
**Claim（论点）+ Evidence（证据）+ Rebuttal（反驳）** 三元组：

- **无证据不立论**：缺少可引用证据的论点直接判定 invalid，不计入计分。
- **结构化反驳**：`data`（对立证据）/ `magnitude`（置信度不足）/
  `scope`（缺量化依据）/ `logic`（无反证）/ `timeliness`（时效性二次质证）。
- **2-3 轮**：第 1 轮立论与反驳，第 2 轮对"未被有效反驳"的核心论点做时效性质证。
- **可计分**：`论点置信度 × (1 - 反驳力度)`，输出多空占比、未解分歧、共识与免责说明。
- **交叉质询**：看多分析师**自我披露的风险**会被空方用作论据（最有价值的素材）。
- 全程离线确定性、结果可复现（同输入同输出），有 LLM 时仅做措辞增强。

## 四、模块三：回测审计 —— AST 静态审计（已完成）

`core/quant/ast_bias_scan.py`（9 条规则 A01–A09 + 综合）

运行时"截断重算法"要求先跑通代码；AST 静态检查在**执行前**就能定位到 文件:行，
两者互补。输出统一为 **缺陷 × 证据 × 严重度 × 影响 × 修复**：

| 规则 | 命中内容 | 级别 |
|------|---------|------|
| A01 | `shift(-n)` / `pct_change(-n)` / `diff(-n)` | FATAL |
| A02 | `bfill()` / `fillna(method='bfill')` | FATAL |
| A03 | `rolling(center=True)` | FATAL |
| A04 | 全样本 `.mean()/.std()` 归一化（带窗口上下文判定，零误报） | WARN |
| A05 | 循环内 `i+n` 前向索引 | WARN |
| A06 | 未来语义命名/列名（future/fwd/next/target/label） | INFO |

已接入 `core/quant/backtest_auditor.audit_strategy()`：作为报告的**第一部分**
（`static_scan` 字段），命中致命项即整体判定不通过并在摘要中点名；
放在既有 8 条规则之外，不污染原评级口径。

## 五、数据管道可靠性（已完成两个）

### 1. `core/chronoaudit.py` —— 时间完整性审计（C00–C08）

专抓"静默损坏回测"的时间缺陷：重复时间戳、时间倒序、未来时间戳、
非交易日 bar、间隔跳跃、**时区/夏令时漂移**、**bar-stamping 约定**（收盘时刻打戳
意味着该 bar 的收盘价在其时间戳时刻才可知 → 隐蔽前视偏差）、采样频率不一致。
`gate()` 提供回测准入闸门，不合格数据拒绝进入回测。

### 2. `core/data_reconciler.py` —— 多源行情交叉核对

同时取多源同一标的 → 计算共识价 → 逐源偏差 → 时间戳一致性 → **质量打分选源**
（一致性 + 新鲜度 + 字段完整度 + 速度）→ 主源异常自动切换备源。
单源失败只降级不抛异常；纯函数 `reconcile()` 完全可离线单测。

## 六、合规治理：合规数字孪生 + SAFR 检查点（已完成）

`security/compliance_twin.py`

- **Agent Identity**：代理身份、委托人、能力集合、授权层级。
- **Controls Repository**：授权、暴露限额（单笔/日累计）、频控、证据质量门槛。
- **Disposition Engine**：`auto_execute` / `escalate` / `deny` / `observe` 四种处置，
  每条都带可解释理由；不可逆或监管敏感动作 → 允许执行但全程留痕（observe）。
- **Tamper-evident Audit Log**：哈希链，任何一条被篡改 `verify()` 即失败。
- **合规数字孪生**：真实执行前先在孪生环境**模拟一次**（零副作用），
  通过才允许真实执行；可注入外部语义评审器（如 LLM 评审员）作为"校准评估器"。
- 已可一键接入工具层：`agent_core.add_tool_gate(twin.gate_for_tools())`。

## 八、本轮踩坑（已写进项目记忆）

1. **中文引号**：工具描述里写 ASCII 双引号直接 SyntaxError → 统一用「」；
   每次写完后立即 `compile` 校验（本项目已多次栽在这上面）。
2. **Edit 缩进**：一次替换把循环体并进 `if` 分支，导致多方论点全部丢失
   → 结构性改动后必须做功能验证，不能只看"跑通不报错"。
3. **run_all 判 FAIL 看 stderr 里的 "Traceback"**：故意制造异常的测试要临时静音 logger，
   否则会被判为失败（误报）。
4. **误报比漏报更伤**：AST 规则必须加窗口上下文判定，否则
   `rolling(20).mean()` 会被当成"全样本归一化"误报。
